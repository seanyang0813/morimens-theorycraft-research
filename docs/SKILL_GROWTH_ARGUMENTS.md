# Growth expressions and numeric skill arguments

`engine/skill-growth.mjs` connects explicit formula names and original coefficients to the authored numeric expression evaluator. Formula expressions come from BattleApi.Data; values are not inferred from formula names. The resolver sets GrowArgValue for each coefficient, evaluates the named expression, then stores GrowArgValue1, GrowArgValue2, etc. SkillLevel is explicit. Trace entries retain the expression, original coefficient and all variable reads.

`tools/skill_growth_oracle.py` evaluates all 106 exported BattleFomula Data expressions through their original compiled FuncTable closures. The 1,272 cases cover levels 1, 2 and 6 and coefficients 0, 0.1, 0.4 and 2. Authored evaluations match exactly, including floating-point operation order. Original parser/name lookup and member mutation are not executed by this oracle.

`buildNumericSkillArguments` evaluates a numeric parameter expression using those growth members plus explicit external variable/function bindings. It then applies the existing ordinary argument normalization: ceil base arguments, then replace them with explicit overrides without another ceiling. A composition test selects the exported-style coefficient 0.4, grows it to 0.8 at level 6, evaluates supplied attack 258 to raw 206.4, then obtains argument 207; an override of 0.5 remains 0.5. This is an arithmetic integration test, not a gameplay prediction or completed character build.

`tools/connected_skill_arguments_oracle.py` now checks original GetSkillArgs -> __CalcBaseSkillArgs with original compiled growth and parameter closures in one Lua state. All 108 cases match the authored arguments and ordered growth-member writes, spanning three skill levels, four supplied attacks, three coefficient pairs and absent/zero/fractional overrides. The harness supplies selected coefficient lists and Para, adapts member storage and expression lookup/environment, and omits descriptions. This closes the numeric argument-construction boundary without claiming original parser or build assembly.

The current interface requires one explicit original coefficient per formula. Original missing-coefficient defaulting, table-form parameter lists, description construction, complete list-field routing, ownership and skill-level derivation remain unfinished. Attack and progression inputs in this connected check are controlled values, not independently captured gameplay properties.
