# Arachne Fate Cut — recovered path, not gameplay verified

Scope: downloaded PC resource 144 / build 51. The selected Frenzy replay's original combat build remains unconfirmed. Provenance: `PC144:ArachneFateCut` in the evidence registry. No output has been fitted and no final-damage support is claimed.

## Accumulation is separate from a hit

Follow-up skill 133381 targets the enemy with least HP. Its second argument is BattleAtkForce × grown coefficient × (1 + caster state 134224 / 100) × (1 + player basic_damage_per / 100) × (1 + player state 135034 / 100). The original coefficient is 12, with BattleFomula1 growth. Resolve the follow-up's actual level independently; Strike's level alone does not establish it.

Season state 134230 routes StateArg3 through command 135033 to player state 135034. The recorded level-10 talent config supplies 100 for this argument. Command 133382 doubles the amount applied to state 134285 when the target has mutation marker 89575 and the caster has season state 134230; otherwise it applies the amount once. This is a separate branch from the season percentage in the skill argument. The target's marker must be established from evidence.

Before applying Fate Cut, the follow-up adds temporary prism states 133390 to all Awakeners and 133460 to the player. State 133390 changes several property slots, including card_damage_per3_n2 by twice its changed layer count. The follow-up can therefore change subsequent card damage even when Fate Cut has not triggered. This timing matters to the Frenzy trace.

## Threshold discrepancy

State 134285's description says that reaching or exceeding the target's HP triggers the kill. Both recovered judgments (on HP change and state addition) instead require `StateOwner.hp < Layer` and no state 136627. Thus the code-derived boundary is strict: equal layers and HP do not satisfy these judgments. This is an explicit discrepancy to test, not a silently corrected tooltip or a gameplay-confirmed rule.

## Triggered damage and temporary changes

Command 133387 first selects a temporary branch marker according to states 90647/94600 and monster_hp_num. Both branches later call BEPassiveDamage with the current Fate Cut layers, one repetition, and subtype argument 1. The branches differ in death presentation/VFX. The effect is not implemented here as unconditional HP removal.

Before the Passive hit, negative target be_passive_damage_per slots 1–3 receive compensating states 150842, 150839 and 150841. Each state adds ChangedLayer to its property and has a maximum of 9999; do not assume unlimited cancellation. Positive be_damage_limit receives state 139115, whose property contribution is minus ChangedLayer and whose maximum is 99999999. State 131118 is temporarily removed when present. Guard state 136627 is installed before the damage. The command then removes Fate Cut, compensating states and branch/guard markers, restoring state 131118 conditionally. State callbacks, restoration semantics and death effects still require full execution tracing.

BEPassiveDamage independently multiplies its input by `(1 + target passive slot / 100)` for each of the three passive slots, applies ceiling, then CalFinalVal and a minimum of one, before calling BeHit with Passive category and isCrit false. Therefore positive passive-taken bonuses can still matter after negative slots are compensated. CalFinalVal, BeHit, caps, shields and callbacks prevent treating this intermediate value as final HP loss.
