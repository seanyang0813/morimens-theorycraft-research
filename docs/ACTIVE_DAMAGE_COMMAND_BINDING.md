# Active damage resolves live parameters per target

The original BEActiveDamage.Damage2SingleTarget returns immediately for a dead target. For a living target it invokes GenParams, reads params[1], calls GetRealDmg with that base and the effect's stored paraPlus, clamps the returned damage to at least zero, obtains IsCrit from the command, and sends the attack to BeHit.

`tools/active_damage_binding_oracle.py` reproduces this boundary using original bytecode. Eight cases reuse an effect across changing fractional/negative/zero bases, with living/dead targets and both crit flags. The script asserts call order, forwarded values, zero clamping and the absence of parameter reads for dead targets before writing `tests/synthetic/original-active-damage-binding.json`.

GenParams is an explicit adapter supplying changing values; GetRealDmg is an identity observer, and BeHit only records the attack. This does not validate the formula, HP mutation, compiled expressions, scheduler, state-add variant or gameplay. The evidence establishes when live binding is required, not complete active-card support.

Original DoEffect initialization is now covered separately by `tools/active_damage_initialization_oracle.py`: 112 parameter combinations plus a missing-target case. The original order is ceil(repeat or 1), add damagetimes_plus, multiply by (1 + damagetimes_per / 100), ceil again, then clamp to at least one. Zero repeat is present, not a missing value. The original stores paraPlus and damage subtype at initialization. The harness supplies a no-op superclass, identity subtype mapping, caster property getters and a DoMultiEffect observer; it does not execute hits or the original scheduler. An empty target table is present and reaches DoMultiEffect; absent targets return before initialization.

`engine/active-damage-command.mjs` now composes this numeric initialization with `ResearchEffectOrder`. Each repetition queues a target child that reads current parameters, resolves damage through an explicit adapter, reads crit and applies the hit. Children generated by the hit drain before the next repetition. A synthetic composition test changes state after each hit and obtains different subsequent values while initial repeat count and paraPlus stay fixed. The per-target behavior is compared with the original binding observations; the full scheduled composition has not run as a connected original execution.

This ordinary numeric subset accepts one supplied target and stops when it dies because retargeting remains unsupported. State-add variants, target generation, delays, lifecycle and expression evaluation are excluded. It is a programming interface for the forthcoming card interpreter, not a newly supported card or a complete JSON battle input. The missing-target original behavior is evidence only; the enqueue interface requires explicit target callbacks.

The existing card-action runner takes independently supplied hit scenarios. It therefore remains a resolved-input experiment. Automatic card-command execution needs a live expression environment feeding GenParams at the per-target boundary, along with original initialization, target generation and effect ordering. Pre-expanding an entire card into immutable damage values would erase interactions that change subsequent hits.
