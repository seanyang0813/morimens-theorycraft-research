# State immunity

`engine/state-immunity.mjs` reconstructs `BEAddStateParent.CheckImmue` for explicit inputs. It is shared state logic, independent of character identity.

All three broad properties are read first: `immue_buff`, `immue_debuff`, and `immue_both_buff`. Positive values block the corresponding buff/debuff classification. Both-type immunity does not block an untyped state. Broad rejection omits the state ID from the tip.

If broad immunity does not reject the request, supplied specific rules are evaluated in order. The property is read for every listed ID, including nonmatches. A matching ID with a positive property rejects the request and includes the state ID in the tip. Missing property values are errors, not assumed zero.

The authored result includes the decision, property-read order, and tip state IDs. `tests/state-immunity.test.mjs` compares all three against 144 original Lua method executions generated by `tools/state_immunity_oracle.py`. The oracle supplies state configuration, property getters, a synthetic specific-state mapping, expression results, and a tip observer. It does not establish automatic build-property derivation or gameplay accuracy.

The general state-sequence experiment accepts these rules in `applyState.request.immune`. It skips immunity evaluation for nonpositive initially rounded requests and records `immunityCalculation` for positive requests. Blocked applications create no state and do not run layer calculations.

## Recovered client catalog

`tools/build_state_immunity_catalog.py` enumerates the original `PropertyImmueState` table and joins literal `BattleApi.Data` state IDs. It also preserves the classification of all 6,973 exported states. The generated `research/evidence/state-immunity-catalog.json` includes source fingerprints and limitations.

The four active properties map vulnerable to 2934/3149, weak to 3469, poison to 3068, and frail to 2564. Their state IDs do not overlap; the exported Lua iteration order is preserved for diagnostic traces. Psychic Trauma 80331 has no buff classification, poison 3068 is a debuff, and counterattack 3905 is a buff. These are client-data findings, not gameplay observations.

`resolveStateImmunityRules({catalog,stateId,properties})` produces the object accepted by `applyState.request.immune`. It rejects unknown state IDs and requires all seven immunity properties explicitly. This conservative input contract also requires specific properties when broad immunity would short-circuit; it does not claim the original method reads those values in that branch. Actual evaluation/read tracing remains in `resolveStateImmunity`. The catalog/resolver are currently offline inputs; website automatic build-property assembly remains unfinished.
