# Post-damage state trigger payloads

The reconstructed `damageTriggerPayload` handles the bodies of `BSTAfterBeActiveDamage`, `BSTAfterPassiveDamage`, `BSTAfterFixedDamage`, and `BSTAfterAttackedByTentacle`. It does not implement generic `TryTrigger` eligibility, listener registration, or the later `Trigger` command execution.

All four first look up the target and call generic eligibility with the target's camp and UID. Active, Passive and Fixed then reject mismatched damage categories. Tentacle does not check the category inside its handler; its registration on `AttackedByTentacle` supplies that restriction. Calling it for every `BeDamage` would be incorrect.

Active and Passive mode None uses `castDamage`, independent of actual HP loss. Unblocked mode rejects nonpositive `realDamage`, then forwards `unBlockedDamage`. CritDamage mode requires the critical flag and forwards `realDamage`, even when zero. Fixed always forwards `castDamage`, with `realDamage` as triggerValue2. Active additionally forwards blocked damage as triggerValue2 and actual loss as triggerValue3. Passive has no extra damage fields.

Active, Passive and Fixed associate the caster and separately the target. Tentacle associates the target and forwards incoming damage. This difference must be preserved when later command expressions select an associator.

These handler bodies match 240 original-runtime cases generated by `tools/damage_trigger_oracle.py`. The fixtures deliberately include category mismatches and unreachable standard effect flags to probe filters. Generic eligibility is supplied, so a successful handler result is not proof that a real boss state activates. Old Embers' resource limits, command targeting, exclusions, listeners and death/phase lifecycle still need complete integration and gameplay validation.

## Shared eligibility now recovered

`engine/trigger-eligibility.mjs` implements original `BattleStateTriggerServer.TryTrigger` separately. Deleted states return false first. If a role UID is supplied and the owner is a monster, the predicate returns whether the UID equals that owner's UID, before considering ally/enemy camp settings. Otherwise `isEnemy` selects different-camp matching; the default selects same-camp matching. An absent UID is represented explicitly by null; numeric zero is present and truthy in Lua.

This predicate matches 64 original executions from `tools/trigger_eligibility_oracle.py`. A composition test connects it to the Active damage handler and distinguishes hits on the state-owning monster from hits on another same-camp monster. It preserves incoming damage as the trigger value even when actual HP loss is zero. This checks the recovered predicate and payload handler, not the later callback's command conditions, deletion timing, or an actual boss encounter.
