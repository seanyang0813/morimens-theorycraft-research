# Local calculator website

`website/dist/index.html` is the general resolved-input formula sandbox. The adjacent Actions, States, Timeline, Builds and Rules pages expose bounded command, state, sequence, build and evidence components for human or agent-led theorycrafting. `mouchette.html` preserves the Mouchette/Arachne case study. These pages do not form a complete battle simulator or infer a final build from a character name.

`tools/prepare_local_website.py` prepares 79 explicitly allowlisted authored engine modules plus sanitized catalogs and page assets. It does not publish original Lua, native libraries, keys, screenshots, replay observations or private research directories. The verification suite checks copied engine modules byte-for-byte against their authored sources, along with static references, JavaScript syntax and calculation integrations.

On 2026-09-20, a local HTTP browser smoke test loaded all seven pages in the in-app browser with their expected titles and headings and no browser console warnings or errors. An Active example with base 1000, 150% team Damage Amplification, a critical hit, 150% character Crit DMG bonus and 50% Vulnerability rendered 9,375 with the expected 1,000 -> 2,500 -> 6,250 -> 9,375 trace. The Actions synthetic cost-order example completed with 500 modeled HP lost, zero energy left and two accepted actions. That pass found and corrected four pre-existing mojibake strings on the Actions page, then verified the corrected page from a fresh browser origin. The Rules catalog now contains 118 evidence entries, including the updated 121/121 command and 149/149 row static-compatibility claim. The Build planner's malformed client-build option was corrected and is protected by a static regression check; full interactive build-planner QA remains pending.

This was a bounded smoke test. States, Timeline, Builds and Mouchette were loaded but not interactively exercised; responsive layouts, import/export flows, browser Blob execution and the optional WebMCP surface remain unverified. Browser rendering does not add gameplay validation.

No hosted Site is registered or deployed. There is no `.openai/hosting.json` project ID. The source checkpoint is on GitHub, labeled as unverified research. Deployment as an accurate build recommender remains prohibited until the gameplay prediction and independent holdout gate passes.

Remaining product work includes source-backed character/build normalization, broader action and encounter execution, complete event/HP behavior, full browser and responsive QA, independent gameplay regression, a separately frozen holdout, discrepancy review, and publication only after the original gate passes.
