# General card actions with shared resources and effects

`engine/card-action-timeline.mjs` exports `runCardActionTimeline`; agents can run `node tools/run_card_actions.mjs actions.json`.

The input uses schemaVersion 1, kind `morimens-card-action-timeline`, build `pc-res144-build51`, initialEnergy, target `{hp,block}`, and steps. Each action contains id, cardInstanceId, costInput (without energy), conditions, and exactly one of hits or command. Hits is a nonempty array in the resolved-hit schema; its IDs must be unique across actions. Cards must be distinct supplied instances. Choose interveningEffects `assumed-absent`, or `old-embers-only-assumed` with explicit oldEmbersLayers for supplied-hit actions only.

A command contains rows, variables, offense, targetModifiers, repeatModifiers and immune as described in ACTIVE_COMMAND_EXPERIMENT.md. It cannot supply its own build, target HP/shield or effect scope. Accepted command actions inherit the target state from the sequence and resolve live UpperTarget.hp during hits. Command actions currently require assumed-absent intervening effects; mixing them with Old Embers is rejected. Supplied-hit and command actions can mix under assumed-absent scope. Command traces are stored in each action's command field, with its hits field null; rejected command actions have no command result. Row/hit identities inside commands are scoped by the enclosing action ID.

All input formulas and resource conditions validate before execution, including suffixes that may never execute. Each action checks available energy, pays once if accepted, then executes its supplied hits. HP, shield, energy and optional Old Embers layers carry forward. Rejected cards have a resource trace but no hit trace. Partial lethal actions retain their payment and stop; later actions cannot pay after target death. Nested traces preserve original component calculations and generated effects.

Synthetic integration tests demonstrate fixed-cost then X versus X then fixed-cost, rejected-card damage suppression, payment preservation on lethal multi-hit actions, and Old Embers persistence across actions. These prove authored composition behavior, not independent gameplay accuracy. Existing component evidence remains the source of each local rule; no connected original card-check-to-payment-to-damage execution has been reproduced here.

This is a general experimental action interface, not automatic card/build interpretation. Hit coefficients or command rows, resolved modifiers, target selection and per-card conditions are supplied. X payment does not automatically scale a hit. Refunds, draw/retention/reuse, changing buffs or card conditions, turn gates, death handling and arbitrary reactive states remain unsupported. Empty-effect/buff actions are refused rather than silently ignored. Results remain EXPERIMENTAL with finalDamage null. Additional integration tests cover payment followed by live command execution, rejected-command damage suppression, and shared target state across mixed supplied-hit/command actions.

The local website now exposes this input in `actions.html`, with a synthetic command/payment example, order reversal and per-action resource/target transitions. Results carry the verified runtime fingerprint; raw input alone is not runtime-pinned. The UI reuses this engine without copying its calculations. Automated event-level and verified-module checks cover execution, changed order and invalid-input clearing; browser visual QA is pending.
