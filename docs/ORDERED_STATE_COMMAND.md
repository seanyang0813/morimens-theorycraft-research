# Ordered state and damage command

`engine/ordered-state-command.mjs` adapts a narrow exported command shape into the existing state-sequence engine while preserving row order. It currently accepts unconditional `BEAddState`, `BERemoveState` and `BESubStateLayer` rows, `BEGainUltiEnergy` for the command caster, single-parameter `BEGainBlock` and `BEHeal` for the caster or supplied target, and ordinary `BEActiveDamage` or `BEPassiveDamage` rows against that target. A state may belong to the caster or target. Every state definition, application request, initial live property, energy context, Block/Heal formula and recipient snapshot, and numeric command variable remains explicit.

Block gain uses the recovered `ShowBlockFormula`, recipient `gain_block_per`/`gain_block_plus`, and the `max_hp`/`block_max_per` storage cap. A target Block row changes the live shield consumed by later damage rows, so reversing a 200-Block row and a 100-damage row changes modeled HP loss from 0 to 100. Caster Block is tracked separately. The numerical path matches 607 original formula executions, 144 original recipient-modifier executions and 160 original storage executions; the mixed command composition is authored and is not a connected original full-command execution.

Heal uses the recovered `ShowHealFormula`, recipient `be_heal_per`/`be_heal_plus`, and `BattleUnitBase:Heal` HP rounding/cap behavior. Its numerical path matches 607 original formula executions, 144 original recipient-modifier executions and 120 original storage executions. A target at 900/1000 HP that receives 200 Heal before 300 damage finishes at 700; reversing those rows finishes at 800 because the early Heal overflows. Caster HP is tracked separately. Repeated or multi-target Heal, events and revival remain outside this subset.

Unlike the terminal-state runner, state rows may appear before, between or after damage rows. Later damage conditions and parameters can use an explicitly bound live `GetStateLayer` query, and damage uses property changes made by earlier states. Death stops later rows through the existing sequence boundary.

Passive rows reuse the recovered original repeat shape, the separately tested Passive pre-hit formula and the shared immunity, shield and HP path. Each repeat reevaluates its base expression, so `UpperTarget.hp` observes earlier hits. The current subset accepts one supplied `UpperTarget`, an explicit static snapshot of the three Passive target multipliers and dimension modifier, and subtype zero. It does not yet bind Passive properties to state mutations. A 111-point Passive hit after 50 target Block loses 61 HP; reversing those rows loses 111 HP and leaves 50 Block, demonstrating the preserved row order.

The first connected real command fixture is Cmd45948. Its first row applies State19534 Vulnerable to `UpperTarget`; its second row deals Active damage to the same target. With a supplied base of 100 and neutral remaining modifiers, the ordered execution deals 125. Reversing the rows deals 100 before applying Vulnerable. The exported 350 ms `DelayTime` is retained in the row plan but treated as inert only because the experiment requires `otherEvents: "assumed-absent"`.

Removal reverses the stored property contribution once. Layer subtraction follows the recovered `SubLayer` order: reduce layers, update a `ChangedLayer` contribution, record the change, and run life end if the state reaches zero. Caster-layer attribution remains excluded.

The same ordered runner can now execute the three effect types in actual Cmd57564: damage, caster ultimate-energy gain and caster State2669. Energy uses the recovered capped gain boundary. A later damage row may read `CmdCaster.ulti_energy`, using the value after earlier supported energy rows execute. State-mutation expressions still require supplied static variables.

The runner rejects unsupported effects, unknown row fields, conditional state rows, automatic target acquisition and mismatched state owners or layers. State-row expressions currently use supplied numeric variables; live state queries are connected for later damage rows. Fixed and Pure command rows remain outside this ordered subset. This is an authored component composition, not an independently validated gameplay prediction or a complete command VM.
