# Hit-to-Old-Embers composition

`engine/old-embers-hit-timeline.mjs` connects the resolved-hit timeline's numeric BeHit payload to the existing Old Embers activation, target selection, phase/command scheduler and HP-attribute-loss helper. The same target HP, shield and Old Embers layers persist between supplied hits. The agent command is `node tools/run_old_embers_timeline.mjs timeline.json`.

Use the resolved-hit timeline input with interveningEffects explicitly set to old-embers-only-assumed and an explicit oldEmbersLayers integer. This scope models an ordinary visible monster with one unbanned non-relic state, empty temporary marker states, no blocker states, no other reactions, and no HP-loss immunity/limits. Synthetic role IDs are internal labels, not reconstructed gameplay identities. State mutations and inactive lifecycle hooks remain adapters. Each activation creates a fresh research command; original cached/reentrant command behavior is not reproduced.

Each hit trace includes generatedEffects with parentStepId, stable row ID, row specification, state before/after and any HP calculation. Fixed/Passive weighting and Pure non-activation use the existing handler implementation. Depletion removes the modeled state for later hits. A lethal ordinary hit stops before trigger execution; lethal generated HP loss stops before subsequent command rows. Remaining stack/marker cleanup is deliberately unresolved across that boundary.

Composition regressions demonstrate two shielded Fixed hits of 10 causing zero direct HP loss but 15 Old Embers HP loss each, with layers 100 → 95 → 90; depletion at three layers causes nine HP loss once; Pure hits leave the state unchanged. These are synthetic composition cases, not independent gameplay observations and not connected original-runtime validation. Component runtime evidence does not automatically validate this composition.

Next: drive the original damage event and state activation through the same original Lua target, then compare generated HP/state transitions. Card legality, other reactions, complete lifecycle and death handling remain required for the general simulator.

## Original payload bridge

`tools/old_embers_argument_bridge_oracle.py` now extends the retained original hit payload through the original matching handler, the original compiled State80575 `TriggerValue*0.5` expression, and the original parser's `Arg1` fallback with empty skill arguments. Its 32 cases cover Passive/Fixed damage, shields, immunity, and odd/fractional input damage. Incoming resolved damage 1 produces argument 0.5; 3 produces 1.5; base damage 101.25 first resolves to incoming damage 102 and produces argument 51. The state fallback does not apply ordinary skill-argument ceiling. The authored composition agrees on incoming damage and generated row arguments.

This harness calls the components directly. `GetValueListByCmd` invokes the original expression through an explicit adapter, and `string.replace` is supplied. Eligibility and role lookup remain supplied; automatic dispatch, full parser environment/cache, state activation, generated row effects and gameplay are not established by this check. Original payload tables remain in one Lua state, but this is still a bounded bridge rather than a full original battle execution.

The next boundary is now covered by `tools/old_embers_expression_oracle.py`: 64 sequences evaluate original compiled conditions and parameters for both command IDs with live marker/stack adapters. The authored iterator agrees for zero, fractional and integer arguments; depleted/nondepleted stacks; and blocker-state presence. Python supplies row iteration and applies marker/stack changes, while HP effects are only recorded. This does not execute the original command parser, scheduler or state-effect objects. Do not combine this evidence label with the payload bridge to imply a full original hit-to-command execution.

`tools/hit_trigger_bridge_oracle.py` now passes the original Lua table generated by the original effect → BeHit → HP mutation chain directly to the original OnBeDamage handlers. The 54 cases cover Passive/Fixed/Pure, three shield values and general damage immunity; category mismatches are deliberate. Authored calculateDamage → hitTriggerValues → damageTriggerPayload matches all results. Fully shielded or immune damage retains incoming castDamage for eligible None-mode handlers. Pure fails the category filters.

This validates the payload bridge, not automatic event dispatch or the complete Old Embers activation. Eligibility is supplied true and role lookup is an adapter. Command rows, generated HP loss and state mutations are still outside the connected original-runtime comparison. The controlled composition's immunity case assumes no separate HP-attribute-loss immunity, which is a distinct property.
